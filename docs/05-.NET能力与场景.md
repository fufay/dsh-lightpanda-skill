# 05 · .NET on HarmonyOS（能力与场景）

> 本文是 `docs/00` 的专题拆分：**oheco .NET 10 移植**的安装、能力图、使用方式、边界与坑。
> 结论：**.NET 在鸿蒙上可用于 CLI / 类库 / ASP.NET / NativeAOT / Godot C#（headless + HAP），不做 .NET 桌面窗口 GUI**；HAP 签名/装机细节见 `docs/04`。
> 实测记录（本机）：mono-harmonybrew `docs/13`（SDK/ASP.NET/NativeAOT/Godot headless）、`docs/14`（Godot C# HAP）、`docs/15`（覆盖矩阵）。

## 0. 能力图（一页）

```text
.NET 10 (oheco, RID=openharmony-arm64)
├─ CLI / 工具              ✅ dotnet new/run/build（JIT）
├─ 类库 / NuGet             ✅ restore/build
├─ ASP.NET Core (Kestrel)   ✅ dotnet run / 自包含 publish（HTTP 200）
├─ NativeAOT                ✅ 可编译；独立可执行需手工重签；HAP 内走 linker 签名
├─ Godot C#（headless）     ✅ 最小工程 / godot-demo 副本 autoload
├─ Godot C# → HAP           ✅ NativeAOT 共享库；无 runtime、无 JIT ACL
├─ Worker / gRPC / Blazor Server  ⚠️ 理论可用，未单独验证（不追）
├─ Blazor WebAssembly       ❌ 需 wasm workload（oheco 不含）
├─ WinForms / WPF           ❌ Windows-only，不做
├─ MAUI / WinUI             ❌ 需 workload + 平台窗口后端
├─ Avalonia / GTK# 等       ❌ 无 OHOS 窗口后端，不做
└─ IIS / HTTP3 / Kerberos   ❌ 不在 oheco 范围
```

**UI 边界**：鸿蒙上不做 .NET 桌面窗口；UI 用 **HAP + ArkUI**（见 `docs/04`），Web UI 由本地 ASP.NET 提供。

## 2. 常用场景

### 2.1 CLI / 控制台

```sh
. /storage/Users/currentUser/.dotnet-ohos/env.sh
dotnet new console -o hello && cd hello && dotnet run
```

### 2.2 ASP.NET Core

```sh
dotnet new web -o web && cd web
dotnet run --no-launch-profile --urls http://127.0.0.1:5000
# curl http://127.0.0.1:5000  → 200（Kestrel）
```

自包含发布（产物是带 `.codesign` 的 ELF，可独立运行）：

```sh
dotnet publish -c Release -r openharmony-arm64 --self-contained true
./bin/Release/net10.0/openharmony-arm64/publish/<app> --urls http://127.0.0.1:5001
```

### 2.3 NativeAOT

```sh
dotnet new webapiaot -o aot && cd aot
dotnet publish -c Release -r openharmony-arm64 -p:PublishAot=true
```

- 产物：`publish/<app>`（ELF，约 11 MB）。
- ⚠️ **publish 的签名 target 会报 `.codesign already exists`**（linker 已写签名），且 linker 签名对 `exec` 不生效；需手工重签：
  ```sh
  OBJCOPY=<CLT>/sdk/default/openharmony/native/llvm/bin/llvm-objcopy
  SIGN=<CLT>/sdk/default/openharmony/toolchains/lib/binary-sign-tool
  "$OBJCOPY" --remove-section .codesign publish/<app> nosign
  "$SIGN" sign -inFile nosign -outFile signed -selfSign 1
  chmod 755 signed && ./signed --urls http://127.0.0.1:5005
  ```
- 先 `mkdir` 输出目录再 publish；`dotnet publish` 因签名 target 可能返回非零但产物已生成，按“文件存在 + 能否执行”判断。

### 2.4 Godot C#

- Godot kit 的 C# 支持需要本 SDK（`dotnet-sdk 10.0.401-ohos.2`）与 `DOTNET_ROOT`；
- headless：最小 C# 工程 / godot-demo 副本 autoload 均可跑（`CSHARP_OK`）；
- **HAP**：kit 导出时自动生成 **NativeAOT 共享库** `libgodot-csharp-game.so`，HAP 内**无 runtime/托管 DLL、无需 JIT ACL**；真机安装/启动/进入玩法已通过（`docs/14`）。
- 两个必须注意的坑：
  - `.sln` 必须用 `dotnet new sln -f sln`（.NET 10 默认 `.slnx`，Godot 不认）；
  - csproj 加 `<OpenHarmonyCodesignEnabled>false</OpenHarmonyCodesignEnabled>`（否则导出时 `dotnet publish` 二次签名冲突）。
- **Godot 4 不支持 C# 的 Web 导出**（引擎级限制）；Web 优先项目保持 GDScript。

## 3. 工具链依赖（官方优先）

- `dotnet build/publish` 需要 **`binary-sign-tool`** 在 PATH：默认用 CLT
  `<CLT>/sdk/default/openharmony/toolchains/lib/binary-sign-tool`（brew 同名工具仅 legacy）。
- **NativeAOT** 还需 CLT 的 `native/llvm/bin`（clang/lld/llvm-objcopy）。
- 临时目录：启动器默认应用私有 tmp；覆盖用 `DOTNET_OHOS_TMPDIR`。
- 网络：GitHub Release 直连不稳，用宿主代理；VM 内可走 SSH 反向隧道。

## 4. 边界与不做

- ✅ 覆盖：CLI/类库/ASP.NET/自包含发布/NativeAOT/Godot C#（headless + HAP）。
- ❌ 不做/不可用：WinForms/WPF（Windows-only）、MAUI/WinUI（workload + 无 OHOS 后端）、Avalonia/GTK#（无窗口后端）、Blazor WASM（缺 wasm workload）、IIS/HTTP3/MsQuic/Kerberos。
- ⚠️ 未验证且不追：Worker Service、gRPC/SignalR/Blazor Server 单独用例、调试器/热重载。
- **不要**装 oheco `oo`、不要依赖其包目录；**不要**把 Classic Mono 当作现代 .NET 方案。
- 许可：MIT；保留 `LICENSE`/`THIRD-PARTY-NOTICES`，不要暗示官方。
